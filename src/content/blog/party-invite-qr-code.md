Someone in the group chat asks where the party is, and you type the address for the fourth time, then the door code, which is a different number from the one in the first message. Then someone's car can't fit the street, and the answer is three screens up, under a meme. A QR code on the door fixes the typing. The question is what the code opens.

## How to make a party invite QR code

The code is a picture of a link, and a phone camera opens it. The guest lands on the plan. Four steps, in the order you do them:

1. **Settle the plan first.** The date, the place with its address, what guests bring, and the entry rule, which is the private part.
2. **Put the public part on an editable page.** One page holds the date, the place and what guests bring; the entry rule stays in the group chat or the group's private invite.
3. **Turn the link into a QR code.** Any QR generator encodes a URL. Scan it on a second phone before printing.
4. **Put the code where people will see it.** On the door, on a table card, and in the group chat. The private part stays with the group. The code that fails is the one that stayed in your notes app.

## What to put behind the code

The code is only as good as what it points at. Point it at an address alone and that is all the guest gets: the street name, nothing else. The plan carries four things, and only the public ones go behind the code:

- **The time and the place, with the full address.** The actual street and number, because the guest who hasn't been there is the one scanning. If the invite can carry a place with a map link, that saves the "which direction?" call.
- **The entry rule, in the private version.** The door code, the buzzer number, the name to give at the door. The group's invite carries it, and the code printed on the door leaves it out, because the door is public.
- **What guests bring.** One line each: drinks, dishes, and the cake. The list stays short, and it stops the double-baking.
- **The small print that stops phone calls.** "No cover charge." "The kitchen is open until one." The fewer the surprises, the fewer messages at 9 p.m.

A pasted address in the group chat can't carry this. It scrolls under the memes and the "who's bringing what" thread, and on the night of the party the useful version is four screens down, under a joke. We wrote about why that happens in [why plans die in the group chat](/blog/group-chat-plans/).

## Where the code goes, so it gets scanned

- **On the door.** The guest who's about to buzz in is the one who needs the plan, and the door is where the plan gets read. Print the code there.
- **On a card at the table.** For the latecomer who missed the chat message and the door together.
- **In the group chat as an image.** The guest who joined the conversation after the address was typed gets the code instead of the scrollback.

A phone's built-in camera opens a QR code that points to a web page, on iPhones and Android phones alike, so the guest side installs nothing. Print the code dark on light, with a clear margin around the pattern, no glare from lamination, and big enough that a camera reads the pattern from an arm's length. A code you can't read off the print is a code you retype by hand, which is the thing you were trying to avoid.

## What the code can't do

A QR code on the door is public knowledge. Anyone who can see it can scan it, and scanning opens whatever is behind the link. So behind a public code only goes what's okay to publish: the date, the place, what people bring.

The door code is not that. It lives where the group can read and a stranger can't: the group chat, or the group's private invite, where only invited people can see it. At the door, a name check or a door code does the last bit of work.

The stage-by-stage plan for keeping the night alive from the first message to the door is in [how to plan a night out](/blog/plan-a-night-out-with-friends/), and the case for keeping the party's plans off a public feed is in [why your group's plans shouldn't live on a public feed](/blog/privacy-for-a-party/).

Two more limits. The code stores a fixed link, so if the plan moves, the change has to happen on the page behind it. And once the code is printed, it's out of your hands: a new plan means a new print. The link is the part that can change. The picture can't.

## The one thing to do differently

Put the plan in the invite before you make the code: the time, the place with the full address, the entry rule, and what people bring. Then turn the link into the code and print the public part at the door. Guests scan instead of typing, the plan updates in one place, and the message at 9 p.m. stops being "so where is this again?"
